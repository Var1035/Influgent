------------------------------------------------------------------------------
1. PROJECT SUMMARY
------------------------------------------------------------------------------

Content creators spend hours every day deciding what to post. They scroll
through YouTube, Reddit, Instagram and other platforms trying to guess which
topics are rising, and by the time they act the trend has often peaked.

This project is a web application that does that research automatically.
An influencer selects the content categories they care about (for example
fitness, food, tech, travel, gaming). Every day the system collects recent
popular content for those categories from multiple platforms, uses AI to
group the content into topics, measures which topics are rising fastest, and
then produces ready-to-use content suggestions: the topic, why it is
trending, a hook, a script outline, a caption, hashtags, and the best format
and length.

In Phase 1 the system uses two sources only: YouTube and Reddit. Once the
suggestion quality is proven with real influencers, Instagram and Facebook
are added, followed by AI-assisted video editing.


------------------------------------------------------------------------------
2. PROBLEM STATEMENT
------------------------------------------------------------------------------

- Creators do not have time to monitor many platforms every day.
- Trend tools that exist are often expensive, generic, or only show what is
  already popular, not what is about to become popular.
- Knowing a topic is trending is not enough; creators also need a concrete
  idea they can film today (hook, script, caption).
- Small and mid-size creators, especially in India and regional-language
  markets, are poorly served by existing tools.


------------------------------------------------------------------------------
3. OBJECTIVES
------------------------------------------------------------------------------

1. Collect trend data daily from YouTube and Reddit for user-selected
   categories and for the overall (all categories) view.
2. Use AI to turn raw posts into ranked topics with a momentum score.
3. Generate specific, actionable content suggestions per influencer.
4. Deliver results through a clean dashboard and a daily digest.
5. Validate with 10 to 20 real influencers before expanding to more platforms.
6. Keep every data source replaceable so that changes in platform access do
   not break the product.


------------------------------------------------------------------------------
4. TARGET USERS
------------------------------------------------------------------------------

- Primary: individual influencers and short-video creators (YouTube Shorts,
  Instagram Reels).
- Secondary: small social media agencies managing several creators.
- Later: brands looking for trending topics in a category.

------------------------------------------------------------------------------
6. FUNCTIONAL REQUIREMENTS (DETAILED)
------------------------------------------------------------------------------

6.1 AUTHENTICATION AND PROFILE
- Sign up and log in with email and password, plus Google sign-in.
- Profile: name, main platform(s), language, audience region, niche notes.
- Password reset by email.

6.2 CATEGORY SELECTION
- A preset list of categories (fitness, food, tech, travel, gaming, fashion,
  finance, education, comedy, news, lifestyle, and more).
- Users choose 1 to 5 categories in the MVP.
- Users may add a custom niche keyword (for example "home workouts for
  beginners"). Custom niches are mapped to search terms and relevant
  subreddits.
- Each category is mapped on the backend to: YouTube category IDs and search
  keywords, a set of relevant subreddits, and optional extra keywords.

6.3 DATA COLLECTION
YouTube:
- Most-popular videos by category and region.
- Recent videos matching category keywords, sorted by view count and date.
- Fields stored: video id, title, channel, published time, views, likes,
  comment count, duration, tags, description, thumbnail URL, and a snapshot
  time so growth can be measured between days.
Reddit:
- Top, hot and rising posts from the subreddits mapped to each category,
  plus r/popular for the overall view.
- Fields stored: post id, subreddit, title, body text (when public), score,
  upvote ratio, comment count, created time, permalink, and snapshot time.
- Collected through a provider (see section 9) and kept behind a replaceable
  "source" module.
Scheduling:
- A daily job collects data for all categories that at least one user has
  selected. A lighter job may run more often for fast-moving categories.

6.4 CLEANING AND PREPARATION
- Remove duplicates and reposts.
- Remove spam, very low-quality or clearly irrelevant posts.
- Remove posts older than the freshness window (for example 7 days).
- Filter out NSFW and unsafe content.
- Normalize all sources to one common format (platform, id, title, text,
  engagement numbers, timestamps, url, category).

6.5 AI ANALYSIS
- Topic clustering: group similar posts and videos across platforms into
  topics using text embeddings and clustering, then have the AI model name
  and summarize each topic.
- Momentum score: compare engagement between snapshots to estimate how fast
  each topic is rising, not only how large it is. Cross-platform presence
  (a topic rising on both YouTube and Reddit) increases the score.
- Explanation: for each top topic, the AI writes a short "why this is
  trending" note based only on the collected data.
- Audience-question mining: extract common questions and pain points from
  Reddit posts and YouTube comments to identify content gaps.

6.6 SUGGESTION GENERATION
For each influencer, each day, the system produces a ranked list of
suggestions (for example 5 to 10). Every suggestion contains:
- Topic and category
- Why it is trending (with links to the supporting posts)
- Suggested format (Short/Reel, long video, carousel, text post)
- Recommended length
- Hook (first 3 seconds)
- Script outline (beginning, middle, end)
- Caption and hashtags
- Suggested posting window
- Confidence / momentum indicator
Personalization uses the influencer's categories, language, and feedback
history (saved, dismissed, posted).

6.7 DASHBOARD
- Today's suggestions, sorted by momentum.
- Trending topics per selected category.
- Overall trending view across all categories.
- Topic detail page with the source posts, charts of growth, and the
  generated script.
- Actions: save, dismiss, copy script/caption, mark as posted.
- History of past suggestions.

6.8 NOTIFICATIONS
- Daily email digest with the top suggestions.
- Optional WhatsApp or Telegram digest in a later iteration.

6.9 ADMIN AND MONITORING
- View of collection job status, number of posts collected per source, and
  errors.
- Cost tracker for data provider and AI usage.
- Ability to enable or disable a data source.


------------------------------------------------------------------------------
7. NON-FUNCTIONAL REQUIREMENTS
------------------------------------------------------------------------------

- Reliability: if one source fails, the others still produce suggestions.
- Replaceability: every platform is a plug-in module with the same interface.
- Performance: dashboard pages load in under 3 seconds; daily pipeline
  finishes within a fixed window (for example before 6 AM local time).
- Security: secrets stored only in environment variables; passwords hashed;
  HTTPS everywhere; per-user data isolation.
- Cost control: caps on data pulled and AI tokens used per day.
- Compliance: use public data only; do not store personal information of
  platform users beyond what is needed; respect each platform's terms.
- Scalability: start small, but design the database and jobs so the number
  of categories and users can grow.

9. TECHNOLOGY STACK AND TOOLS
------------------------------------------------------------------------------

DEVELOPMENT ENVIRONMENT
- Google Antigravity (agent-first IDE) for building the project with
  AI agents; Git and GitHub for version control.
- A SPEC.md file in the repository (this abstract is its basis) so that

FRONTEND

BACKEND
- Python 3.11+ with FastAPI

- SQLAlchemy and Alembic for database access and migrations

DATABASE
- PostgreSQL (hosted option such as Supabase or Neon for the MVP)
- pgvector extension (optional) for storing text embeddings

DATA SOURCES
- YouTube Data API v3 (official; free quota, needs an API key)
- Reddit data through Apify (Reddit scraper actors; pay per result; free
  plan includes $5 monthly credit). Kept behind a swappable module.
  Official Reddit API access to be requested in parallel because commercial
  use requires an agreement with Reddit.
- Google Trends (optional extra signal)

AI / ML
- A large language model API for topic naming, explanations, and suggestion
  writing (Claude API or Gemini API; the provider is kept replaceable)
- Text embeddings and a clustering method (for example HDBSCAN or k-means)
  for grouping posts into topics

JOBS AND SCHEDULING
- A scheduler (cron on the host, or a task queue such as Celery / RQ /
  APScheduler) to run the daily pipeline

AUTH AND EMAIL
- Auth library or hosted auth (for example Supabase Auth or NextAuth)
- Transactional email service (for example Resend or SendGrid)

HOSTING AND DEVOPS
- Frontend: Vercel (or similar)
- Backend: a small cloud server or container platform (Render, Railway, or a
  VPS)
- Environment variables for all secrets; a .env.example file in the repo
- Basic logging and error monitoring (for example Sentry free tier)

TESTING
- pytest for backend tests
- Playwright or Antigravity's built-in browser checks for frontend flows

11. END-TO-END WORKFLOW
------------------------------------------------------------------------------

1. Influencer signs up and selects categories.
2. System maps each category to YouTube keywords/IDs and subreddits.
3. Daily at a fixed time the scheduler runs the ingestion jobs.
4. YouTube and Reddit modules fetch data and save it with a snapshot time.
5. Cleaning step removes duplicates, spam and old or unsafe content.
6. Posts are embedded and clustered into topics.
7. Momentum score is calculated using growth since the last snapshot and
   presence on more than one platform.
8. The LLM names each topic, explains why it is trending, and extracts
   audience questions.
9. For each user, the suggestion generator selects the best-fitting topics
   and writes the hook, script outline, caption and hashtags.
10. Suggestions appear on the dashboard and are sent in the email digest.
11. The influencer saves, dismisses or marks suggestions as posted; this
    feedback improves future ranking.

------------------------------------------------------------------------------

- Repository, environment, database schema, categories seed data
- YouTube source module and a first working collection run

15. HOW TO BUILD IT IN ANTIGRAVITY
------------------------------------------------------------------------------

1. Create the project and add this abstract as SPEC.md.
2. Work one phase at a time; give each agent one clear task and review the
   output before the next task.
3. Use parallel agents only after the base exists (for example backend and
   frontend at the same time).
4. Ask agents to write tests and to verify pages in the built-in browser.
5. Commit to Git after every working step.
6. Keep all keys in .env; never paste secrets into prompts.

First task to give an agent:
"Create the PostgreSQL schema from section 10 of SPEC.md, seed the category
table, and build the YouTube source module that collects the most popular
videos for a given category and stores them with a snapshot time."

17. RISKS AND MITIGATION
------------------------------------------------------------------------------

RISK: Reddit access changes (API approval, new restrictions).
MITIGATION: Keep Reddit as a swappable module; apply for official access;
use multiple providers if needed; reduce dependence by adding other signals
such as Google Trends and YouTube comments.

RISK: Platform terms of service and legal exposure.
MITIGATION: Use public data only; avoid personal data; get legal advice
before charging customers; prefer official or licensed sources over time.

RISK: Trends are already peaking by the time they are detected.
MITIGATION: Rank by growth rate between snapshots, not just by size.

RISK: Generic or low-quality AI suggestions.
MITIGATION: Ground every suggestion in collected posts, test prompts with
real influencers, and use feedback to improve ranking.

RISK: Cost overrun from data or AI usage.
MITIGATION: Daily caps, cost tracking in the admin view, smaller test
volumes first.

RISK: Agent-written code containing errors or security gaps.
MITIGATION: Tests, code review of each phase, secrets in environment
variables, and Git history for easy rollback.
